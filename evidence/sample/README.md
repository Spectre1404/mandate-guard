# Sample evidence packet

`evidence-packet.pdf` and `evidence-packet.json` are from a **real Prava sandbox run** on
2026-08-01. Every payment-side step is genuine: session creation, the cardholder's issuer OTP and
passkey approval in Chrome, one-time credential issuance, `report-status`, and the returned
`visa_confirmation: SUCCESS`.

The merchant is the self-hosted Beanline storefront, disclosed in `DISCLOSURE.md`: sandbox-issued
credentials cannot clear a real merchant's processor, and Prava support confirmed a clearly
disclosed self-built storefront is acceptable. The agent rationale and the labelled narrative
section are live `gpt-5-mini` calls.

Regenerate against the real sandbox (spends one session, needs a human at the passkey prompt):

```
.venv/bin/python scripts/run_demo.py happy --prava real --storefront-port 8200
```

Offline path — identical flow against the local `fake_prava`, no quota spent:

```
.venv/bin/python scripts/run_demo.py happy
.venv/bin/python scripts/make_sample_packet.py
```

## The blocked-run packet is environment-independent

`evidence/demo/evidence-blocked.*` (generated by `scripts/run_demo.py blocked`) needs no
real-sandbox equivalent, and there is nothing to re-run. A gate FAIL is terminal *before* any
Prava call: no session is created, no credential is ever issued, and no network request is made.
The chain therefore contains no environment-dependent facts. `run_scenario` refuses
`blocked --prava real` outright rather than implying otherwise.
